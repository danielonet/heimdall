---
title: Glossary
description: Terms used in Heimdall.
---

| Term | Meaning |
|---|---|
| **Adapter** | The code that talks to one family of routers. |
| **Alert** | A finding raised by a detector. Severity CRITICAL, WARNING or INFO. |
| **Acknowledge / resolve** | *Seen it* / *dealt with*. |
| **ARP spoofing** | Pretending to be another device on the LAN by forging address replies; a common man-in-the-middle method. |
| **Auto-block** | A timed, automatic block of a device after a qualifying threat alert. On by default for a new install; you can turn it off in Settings. |
| **Beaconing** | Regular-interval calls to one remote host, typical of malware waiting for orders (C2). |
| **Block** | Remove a device from the network via the router. |
| **Correlation** | Combining two related alerts on one device into one higher-severity incident. |
| **EVE log** | Suricata's JSON alert log. |
| **Honeypot** | A decoy service; any contact is suspicious. |
| **IDS** | Intrusion detection system: matches traffic against known-bad rules. |
| **MAC address** | A network card's hardware address. Phones often use a randomised one per network. |
| **Passive mode** | Running without a router login, finding devices from the ARP table. |
| **PORT TOTAL** | A wired port's byte count, which is not one device's traffic. |
| **Primary router** | The router Heimdall reads devices from. |
| **Quarantine** | Cut internet access but keep LAN access. |
| **Tier** | minimal, intermediate or full: which optional containers run. |
