Install

One command.
Your machine, your data.

Heimdall runs on a Linux machine on your home network, ideally wired. Pick a tier, run the command, open the dashboard.

$ curl -fsSL https://heimdall.it.com/install.sh | bash -s -- --tier=intermediate
# tiers: minimal | intermediate | full. Add --router=passive if yours is not listed.
$ curl -fsSLO https://heimdall.it.com/download/heimdall.deb
$ sudo apt install ./heimdall.deb  # installs Docker and the compose plugin if missing
$ sudo heimdall setup  # tier, router, generates this machine’s secrets
$ sudo heimdall start  # pulls the images; starts now and at every boot
$ curl -fsSLO https://heimdall.it.com/download/heimdall-bundle.tar.gz
$ curl -fsSLO https://heimdall.it.com/download/heimdall-bundle.tar.gz.sha256
$ sha256sum -c heimdall-bundle.tar.gz.sha256 && tar xzf heimdall-bundle.tar.gz && cd heimdall
$ ./setup.sh
$ docker compose pull && docker compose up -d
Do not expose itNever forward ports 3000 or 5000 to the internet. Heimdall is for your LAN. Reach it remotely through a VPN you already trust.

Choose a tier

Tier · minimal

Core stack

Database, cache, backend and dashboard. All eight passive detectors, ML anomaly detection, Nmap, threat intel, block and quarantine. Light enough for a mini-PC or a Raspberry Pi 4-class machine.

Tier · intermediate

+ Honeypot

Adds OpenCanary: fake FTP, Telnet, SSH and HTTP services. Anything that touches one is a critical alert naming the source.

Tier · full

+ Zeek, ClamAV, Suricata

Adds DNS and connection analysis, file scanning and a signature IDS. Needs about 4 GB of RAM and a wired connection that sees your traffic.

Requirements

MachineLinux on the same LAN as the devices you want to watch. A wired port is strongly preferred; WiFi sniffing is limited.
SoftwareDocker with the compose plugin. The installer can add it (--install-docker); the .deb pulls it in.
RouterOptional. Pick yours on the Equipment tab, or choose “Other / not listed” and Heimdall works from its own view of the network.
Architecturex86-64 today. ARM images are not published yet.

What the installer changes

It does

  • Create ~/heimdall (or /opt/heimdall for the .deb) with the compose file and config.
  • Generate secrets unique to this machine in secrets/, readable only by you.
  • Write .env with your tier, interface and subnet.
  • Pull images and start the containers.

It does not

  • Touch your router’s settings or password.
  • Open any port to the internet.
  • Send data anywhere. Optional threat-intel lookups ask public feeds about addresses only if you enable them.
  • Start anything after a .deb install until you run sudo heimdall start.

Verify before you run

Piping a script to a shell asks for trust. Here is how to need less of it.

  1. Read the script. install/get-heimdall.sh is about 150 lines. The page’s command downloads it from the same release.
  2. Check the checksum. Every download has a published SHA-256. 
    $ sha256sum -c heimdall_0.1.0_all.deb.sha256
heimdall_0.1.0_all.deb: OK
  3. Use the manual route. The “By hand” tab does the same thing step by step.

Upgrade

Script: run the same command again. Secrets and .env are kept; the image tag moves. .deb: install the newer .deb, or sudo heimdall upgrade. Database migrations run on start.

Uninstall

Stop it with sudo heimdall stop, remove the package with sudo apt remove heimdall. Your data and secrets stay. To delete everything: sudo heimdall reset (asks first).
